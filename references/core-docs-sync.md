# 核心文档同步（提交前门槛）

## 核心文档集
见 `judgment-criteria.md`。默认集可按项目覆盖：若仓库有 `docs/` 且 README 索引了其中文件，被索引者纳入。

## 差异驱动更新法
1. 跑 `core_docs_relevance_scan.ps1`，拿到：哪些源文件在本次变更集里变了、哪些核心文档交叉引用了这些源文件（导出名、CLI 命令、配置项、路径）。
2. 对每个被标记"需更新"的文档，逐项对照 diff：
   - 变量/导出改名 → 文档里的旧名改新名。
   - CLI 命令变 → 文档示例同步。
   - 文件移动/删除 → 文档路径同步。
   - 新增能力 → 文档补一段（仅当 diff 明确体现该能力）。
3. 不得新增事实：文档里出现的数字、日期、人名、原话、性能指标，必须能在 diff 或现有文档里找到出处。找不到 → 标 `［待补充：…］`，不替作者圆上。
4. CHANGELOG 单独走 `release-versioning.md`。

## 反幻觉红线
- 不编造版本号、不编造 CHANGELOG 条目、不编造文档未支撑的功能。
- 推测标明为推测，不写成事实。
- 改稿涉及不可互换语义（数据结果/意义评价、功能/目标、性能/成本收益）时：删修饰可以，换说法不行。

## 什么时候不更新文档
- 变更只是格式化、重排、注释、纯内部重构且无对外行为变化 → 不动文档，但报告"无需文档更新"。
- 拿不准影响面 → 在计划门槛里列出，让用户裁定，不擅自改。
