# 修复计划表（计划门槛的呈现形式）

`SKILL.md` Phase 3B 第 2 步要求"基于 diff 给出具体可发布化计划，并**列成表**"。本文件就是那张表的结构。

## 表结构（四列，缺一不可）

| 动作 | 目标 | 为什么 | 状态 |
|---|---|---|---|
| <要做的动作，一句话> | <具体文件路径 / 分支名 / 命令对象> | <为什么必须做：指向 diff 里的什么> | 将创建 / 将更新 / 将跳过 / 需你确认 |

- **动作**：动词开头，具体到可执行（"把 `README` 的安装章节改成新 CLI 名"，不是"改进文档"）。
- **目标**：必须是**真实存在的路径**或明确的命令对象；路径照仓库实际形态写（相对仓库根、正斜杠）。
- **为什么**：必须落到 diff 上（哪个文件/符号变了、哪个测试红了）。写不出 diff 依据的条目不该进表。
- **状态**：四选一，语义如下。

| 状态 | 含义 | 批准后是否自动执行 |
|---|---|---|
| **将创建** | 新文件 / 新分支 | 是（本地动作） |
| **将更新** | 改动已有文件 | 是（本地动作） |
| **将跳过** | 考虑过但不做，**必须在"为什么"里写明不做的理由** | 否（本就是不做） |
| **需你确认** | 拿不准 / 有副作用 / 超出原范围 | **否**——必须用户单独答复后才动 |

## 表格示例

| 动作 | 目标 | 为什么 | 状态 |
|---|---|---|---|
| 新建工作分支 | `fix/percent-helpers` | 当前在受保护分支 `main` 上，禁止直接提交 | 将创建 |
| 修正实现 | `src/percent.js` | 未提交改动里 `formatPercent` 的除零分支会返回 `Infinity` | 将更新 |
| 补一条 CHANGELOG 条目 | `CHANGELOG.md` 的 `[Unreleased] → ### Fixed` | 上述修复对使用者可见，属 patch | 将更新 |
| 提交 | 2 个提交（fix / docs） | 一个提交一个意图 | 将创建 |
| 跳过版本 bump | `package.json` | diff 无对外行为变化，仅修 bug，按门槛层判不需要 bump | 将跳过 |
| 未跟踪文件去留 | `notes/scratch.md` | 是半成品，删除会丢用户工作 | 需你确认 |

## ⛔ 本表不批准远程不可逆动作

**推送（`git push`）、开 PR/MR（`gh pr create`）、删远程分支（`git push origin --delete`）、推 tag（`git push <remote> <tag>`）不在本表的批准范围内。**

即使表里写了"推送并开 PR"，那也只是**告知你下一步会做什么**，不是授权：执行到 push 那一刻仍要按 `references/autonomy-and-safety.md` **再做一次独立的最终确认**。计划门槛覆盖的只有本地动作（编辑、`git add`、`git commit`、本地 `git tag`、本地 `git branch -d`）。

> 为什么把这条写得这么重：把 push 混进"一次批准"里，等于用"同意改文件"换走了"同意改远程"，而后者不可逆。

## 非交互环境（无 `ask_user_question`）
把本表**原样写进回复**，然后**停下等确认**——不得自批。见 `references/autonomy-and-safety.md` 的"非交互环境"。

## 红线
- 表里每一行的"为什么"都要能追到真实 diff 或真实信号；写不出就不进表，或标 `［待补充：…］`。
- 不把"将跳过"当垃圾桶：跳过必须给理由。
- "需你确认"的条目**不得**在用户答复前动手。
- 不在一张表里塞 20 行琐碎项——只列有决策价值的（要改什么、要跳什么、要问什么）。
