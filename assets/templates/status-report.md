# 立正收尾报告模板

每次"立正"结束，按本结构向用户汇报。**主叙事全部用大白话**——读者是项目作者（可能是刚入行的开发者）。字段名 / 命令串 / JSON 键一律不进主叙事；要留就放进末尾"📋 技术细节"小节。主叙事必须能脱离技术细节独立读懂。

## 报告结构

```
## 立正汇报

**一句话总结**：<你的项目现在 X，我帮你做了 Y，结果是 Z。>

### 这次帮你做了什么
- <大白话：发现了什么 → 做了什么 → 现在怎样。一条一件事>
  例：我发现一个已经合并完、没人再用的旧分支 feature/old-login，帮你删掉了，分支列表干净多了。
- <没做的事也用大白话说为什么>
  例：项目还没连上 GitHub，所以"同步最新代码""开 PR"这两步先跳过——等你连上远程我再帮你补。

### 你接下来可以做什么（按重要性排）
1. **<建议标题，大白话>**：<现状> → <该做什么> → <为什么对项目好>
   例：**给项目连个 GitHub 远程**：代码现在只在你电脑上，没备份没法协作 → 在 GitHub 建空仓库、把地址给我 → 连上后能备份、能开 PR，项目才算"活"起来。

### PR（如果有）
- <PR 链接，或"还没开，因为…下一步…"，大白话>

---

### 📋 技术细节（可选，给想核对的人；新手可跳过）
> 只放原始信号供核对，主叙事必须能独立读懂。没有就写"无"。
- 默认分支 / 远程 / 本地变更 / 已合并分支候选 / 陈旧未合并 / 受保护 / 版本文件一致性 / 涉及 release / 未推送提交
```

## 写法正反例（对照，别又写成字段名堆砌）

> ❌ **别这样**（字段名堆砌，新手看不懂）：
> 判定：干净态。local_merged_candidates=[]，is_github=false，version_files=[]。pull --ff-only 未执行（无 upstream）。next_steps：配置远程；补 CHANGELOG。

> ✓ **要这样**（大白话，用户立刻知道干啥）：
> 你的项目现在是干净的，没有未保存的改动，也没有需要清理的旧分支。不过有两件事可以做得更好：代码还没连上 GitHub（没法备份也没法在线协作），以及项目标了版本号 0.1.0 但没有更新记录。建议你……

## 红线
- 主叙事每一句大白话；不编造；没做就说没做 + 为什么（大白话）。
- 字段名 / 命令串 / JSON 键 不进主叙事，只进末尾"📋 技术细节"。
- 技术细节是"可选核对"用，主叙事必须能独立读懂。
